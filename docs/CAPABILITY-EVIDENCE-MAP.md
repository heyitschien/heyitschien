# Capability Evidence Map

This map translates capabilities into employer value and the strongest public-safe evidence for **AI Implementation · Technical Solutions** roles.

Profile routing table (shorter): [README capability → evidence](../README.md#what-i-can-own). Public-safe implementation overview: [IMPLEMENTATION-AI-SYSTEMS.md](IMPLEMENTATION-AI-SYSTEMS.md). Public-safe case studies: [AI-WORKFLOW-CASE-STUDIES.md](AI-WORKFLOW-CASE-STUDIES.md).

## Method stages → employer value

| Method stage | Employer value |
| --- | --- |
| Discover workflow | Reduces ambiguity before build begins |
| Structure requirements | Creates implementable, reviewable work |
| Configure / integrate | Moves decisions into working systems |
| Validate expected vs actual | Separates confidence from proof |
| Enable the user | Makes the system operable by another person |
| Document the handoff | Preserves ownership and open dependencies |
| Improve the next implementation | Turns learning into reusable process |

Full methodology: [AI-Orchestrated Systems Engineering](AI-ORCHESTRATED-SYSTEMS-ENGINEERING.md#the-repeatable-methodology). Narrative evidence: [case studies](AI-WORKFLOW-CASE-STUDIES.md).

## Recruiter summary

```text
Discover → structure → configure/integrate → validate → enable → document → improve
```

Primary question this map answers: **What can Chien own in an AI implementation / technical solutions role?** Support judgment remains a supporting capability, not the flagship claim.

## Portfolio interpretation

GitHub history includes shipped products, paid independent delivery, active private systems, prototypes, learning projects, support tools, and forks. These are not equivalent production systems. Public claims stay grounded in public-safe evidence. Private systems may apply the same method at larger scale without disclosing IP, client identity, or unverifiable performance. Domain transfer requires qualified experts where work is regulated or safety-critical.
